# Contributing

Contributions are welcome.

A new motion skill should define more than a visual look. It must explain **what drives the motion**.

## Skill checklist

A proposed skill should include:
- purpose and best use cases
- visual grammar
- motion grammar
- anti-patterns
- implementation guidance
- timing guidance
- quality checks
- a reusable prompt pattern

Keep skills tool-agnostic where possible. Implementation notes may recommend GSAP, SVG, Canvas, WebGL, or other techniques, but the design logic should survive a change of tooling.

## Pull requests

Keep each PR focused on one skill or one clear improvement. Explain what changed in the motion logic, not only the styling.
